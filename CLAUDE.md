# MODERN DRONE — FPV strike simulator (Unity 6, URP, PC, single-player)

## Layout
- All game content lives in `Assets/_Project/`. Code is split into asmdefs under `Scripts/` (namespace `ModernDrone.<Assembly>`):
  Core <- Damage, Drone, Video, Vehicles <- Missions, UI. Editor tools in `Editor/`, tests in `Tests/EditMode` and `Tests/PlayMode`.
- Tunable data goes in ScriptableObjects under `Data/` (warheads, armor materials, vehicles, drones).

## Conventions
- Physics layers are defined in `Scripts/Core/GameLayers.cs` and must match TagManager (checked by EditMode tests).
  `Module` layer is query-only (no physical collisions).
- Physics runs at 250 Hz (`SimConstants.PhysicsHz`). Menu `Modern Drone/Setup/Apply Project Settings` re-applies settings.
- The test scene `Scenes/ProvingGround.unity` is generated by `Modern Drone/Setup/Build Proving Ground Scene`; change the
  builder, not the scene by hand.
- Damage/ballistics math should be plain C# (no MonoBehaviour) so it can be unit-tested.

- Scenes: MainMenu (build index 0) -> Mission_01 / ProvingGround. `Modern Drone/Setup/Rebuild Everything` regenerates
  prefabs and all scenes from the builders in `Editor/`.
- Pilot control settings live in `ControlSettings` (JSON at `Application.persistentDataPath/controls.json`), edited by
  the in-game settings menu (`UI/SettingsMenu.cs`). Don't hardcode keys/axes in gameplay code — use `ControlInput`.
- Vehicles are built in `Editor/VehicleCatalog.cs` with `VehicleKit` (plates / ERA / cages / modules / wheels). When swapping in
  imported models keep the plate and module colliders; visuals are separate children.
- Link/video: `Video/LinkModel.cs` (pure rules), `Missions/DroneLink.cs` (per-frame sampling, failsafe, fiber spool),
  `Art/Shaders/AnalogVideo.shader` via the URP Full Screen Pass on `Assets/Settings/PC_Renderer.asset`
  (installed by `Modern Drone/Setup/Install Video Feed Effect`). EW emitters are `SignalJammer` + `JammerStation`.
- Play mode only ticks while unfocused if `PlayerSettings.runInBackground` is on (needed for automated play checks).

## Workflow
- The Unity Editor runs on this folder (main checkout); edit files here, not in `.claude/worktrees`.
- Remote: https://github.com/Bekzat-sudo/MODERN-DRONE

## Rule: verify against sources
- Before every change or addition to game mechanics (flight physics, link/EW behaviour, damage rules) or to
  vehicle/drone characteristics and functionality, check public sources on the internet (docs, specs, reputable
  articles) and note the source in the commit message or a code comment. Keep numbers at the level of publicly
  reported figures; gameplay balance numbers that are deliberately abstract must be marked as such.

## Rule: use the code graph
- The project has a graphify knowledge graph of the game code in `graphify-out/` (scope set by `.graphifyignore`;
  generated, not committed).
- Before every code change, consult it: `graphify query "<question>"`, `graphify explain "<Class>"` or
  `graphify path "<A>" "<B>"` to find what the change touches (callers, dependents, related tests), and read
  `graphify-out/GRAPH_REPORT.md` for the hub classes (e.g. `VehicleDamageModel`, `MissionController`,
  `DroneController`).
- After every code change, update it from the repo root: `graphify update .` (AST only, no LLM or API key).
  Use `graphify update . --force` after deleting or merging classes (the update refuses to shrink the graph otherwise).
